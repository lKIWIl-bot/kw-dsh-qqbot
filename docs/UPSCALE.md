# 高清放大与显存选择

高清是可选功能，安装高清模型和DSH-Upscale节点后，设置comfyChat.features.upscale=true。QQ仍使用/高清、/高清4K或/生图 高清；处理模式不由普通QQ用户修改。

## 两种处理方式

- **直接分块（tiled，0.1.1新包默认）**：将原图拆成256×256像素块，相邻块重叠32像素，逐块做超分后融合拼接。遇到可捕获的CUDA显存不足时会缩到128×128；128仍不足则报告失败。也可一开始选128。显存峰值较低，通常更慢，边界或跨块纹理可能有轻微差异。分块是同一超分模型处理，不重新扩散生成构图。
- **全图优先（full-first，可选）**：先整张处理，保留全图上下文；只有捕获到普通OOM异常才回退分块。若驱动或系统在OOM异常返回前已经失去响应，程序无法完成回退。8GB显卡不建议用它做首次验证。

两种方式均用IllustrationJaNai原生4倍模型；需要2倍时内部先4倍再缩小，最后调整到目标长边。因此最终写着2K，不能代表中间显存只按2K计算。

## 显存占用怎么理解

以下是**当前节点代码的工作内存预留估算**，不是实测总显存、最低硬件要求或可用性保证。估算主项为处理区域宽×高×18,432字节；还要加模型权重、输入输出、CUDA工作区与其他常驻程序。驱动、Comfy/Torch版本和图片尺寸会改变实际峰值。

| 方式 | 处理区域 | 工作缓冲预留估算（额外开销另计） | 部署建议 |
| --- | --- | --- | --- |
| 全图优先 | 512×512原图 | 约4.5GiB | 8GB不作为默认验收方式；大显存也先用小图 |
| 全图优先 | 1024×1024原图 | 约18GiB | 8GB不适用；即使24GB也需考虑其他模型占用 |
| 直接分块 | 256×256块 | 约1.13GiB | 8GB优先从此模式、512原图、单张2K验证 |
| 直接分块 | 128×128块 | 约0.28GiB | 256仍OOM时选择，额外模型及整图输出仍占内存 |

分块不保证6GB或8GB一定成功，也不会消除整图缓存与系统内存需求。先结束其他GPU任务，按需让Comfy卸载不用的模型，不并行加载Anima和高清模型。DPC_WATCHDOG_VIOLATION等蓝屏需查Windows转储和驱动，不能当成普通OOM靠反复重试解决。

## 切换

先等生成队列结束并停止桥接，在项目根目录执行：

```powershell
node scripts/upscale.mjs show
node scripts/upscale.mjs tiled
# 更保守的小块（可选）
node scripts/upscale.mjs tiled --tile 128
# 恢复全图优先（可选）
node scripts/upscale.mjs full-first --tile 256
```

命令同步image-workflow/upscale.json与2K/4K API模板，不改模型、QQ身份、额度或Comfy启用状态。重启桥接生效；未修改节点源码时无需因切换配置重启ComfyUI。若在Comfy界面手动导入工作流，也要重载修改后的模板，或在DSH节点选相同processing和tile。

直接编辑时：image-workflow/upscale.json中的processing可选tiled或full-first，tile可选128或256；机器人提交任务以这个配置为准。手动界面模板与它独立，因此建议使用上述同步命令。

升级旧部署时先备份自己修改的upscale.json；保留旧文件会保留旧处理方式，不会自动强制覆盖。以show输出为准，8GB用户应主动选择tiled。安装与验证不修改系统驱动或电源设置。
