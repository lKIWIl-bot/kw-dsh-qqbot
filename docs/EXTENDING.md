# 扩展边界

首版文生图只启用官方Anima Base，/生图即默认入口。其他模型家族未注册，不能通过改文件名或QQ传参切换。

## 将来新增文生图后端

1. 在src/lora-discovery.mjs扩展可靠元数据识别；无法确认时继续保留待确认状态。
2. 在src/comfy-loras.mjs的readBases增加配置校验，提供独立工作流构建函数，并在loadLoraWorkflow的backends表注册。Anima当前实现为loadAnimaLora。
3. 为新后端准备独立API工作流，定义提示词、采样、模型和输出节点，不接受模型或QQ用户传入任意路径/节点图。
4. 为单LoRA、多LoRA、底模混用拒绝、额度、权限和结果发送增加离线测试；doctor须能报告其节点和模型缺项。
5. 更新配置示例、帮助和依赖文档，再由部署者主动启用。不要更改现有Anima默认行为。

当前backends是明确的代码注册点，不从文件夹自动加载可执行插件。提示词参考是数据，不能提升权限。

## 工作流替换

默认文生图workflowPath支持Comfy API格式，兼容现有qqbot图结构；也支持符合原转换器约定的UI工作流。应先执行doctor并用测试验证输入输出绑定。不是任意Comfy工作流都能直接接入。高清、图生视频沿用各自固定图及绑定校验。

## 身份和权限

管理员以真实QQ号识别，群昵称不授予权限。群内生图须实际@；昵称触发仅授权聊天。新生成入口必须经过真实消息ticket、生成开关、队列和额度校验，不能新增直接绕过后台的MCP接口。

## 已提供的独立扩展

video使用扩展API v1，对应正式版0.1.0。安装、启停、移除和维护见根EXTENSIONS.md。正式包保留受控适配接口；视频生成实现、工作流和模型来源位于独立扩展，不能从QQ消息提供扩展路径或动态装载代码。扩展开发须同步清单、摘要、版本、doctor和离线安装测试。
